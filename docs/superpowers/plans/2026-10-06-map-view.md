# Map View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the flight page into a full-screen MapLibre map with the flight info floating on top: departure card and arrival card, the elapsed-path strip kept, a route arc and a plane marker on the map.

**Architecture:** Pure geo maths in `src/lib/flight/geo.ts` (tested first). `FlightView` (server component) computes the route line and plane position and passes plain serialisable props to `FlightMap`, a client-only MapLibre component loaded with `next/dynamic` (`ssr: false`). The cards, status pill and path strip are absolutely positioned overlays on top of the map; the overlay layer ignores pointer events except on the cards and buttons, so the map stays draggable.

**Tech Stack:** maplibre-gl (installed version is 6.x: read `node_modules/maplibre-gl` types and docs for the exact API, projection/globe option included, instead of relying on memory), CARTO "Voyager" GL basemap (free, no key), Next.js 16 App Router, React 19, TypeScript, Vitest (happy-dom), Playwright.

Design agreed with the owner:
- Phone: map fills the screen; status pill + departure card at the top, the elapsed-path strip directly under the departure card, the arrival card at the bottom with "Check another flight". Cards are compact (photo becomes a slim strip) so the map stays visible.
- Desktop (min-width 900px): departure card on the left, arrival card on the right (not top/bottom); status pill top-centre; path strip floating bottom-centre; "Check another flight" bottom-left or bottom-right of the arrival side, owner's tweak later.
- Plane position: `flight.position` (real) if present, otherwise estimated from `flightProgress` along the great-circle arc; the estimate is labelled "Estimated position" on the map. No plane when cancelled.
- The route arc must be safe across the date line (LAX to NRT crosses it): use unwrapped longitudes.
- Globe at low zoom if the installed MapLibre supports it (check the docs); flat map is acceptable if not.

**Files:**

- Create: `src/lib/flight/geo.ts`, `src/lib/flight/geo.test.ts`

**Interfaces:**
- Produces (`geo.ts`):
  - `interface LatLon { lat: number; lon: number }`
  - `distanceKm(a: LatLon, b: LatLon): number` (haversine, Earth radius 6371 km)
  - `interpolate(a: LatLon, b: LatLon, fraction: number): LatLon` (great-circle point; fraction 0 = a, 1 = b; fraction clamped to 0..1; if a and b are identical or antipodal-degenerate return a)
  - `bearing(a: LatLon, b: LatLon): number` (initial bearing in degrees, 0..360, 0 = north)
  - `greatCircleLine(a: LatLon, b: LatLon, steps?: number): [number, number][]` ([lon, lat] pairs, default 64 steps, `steps + 1` points; longitudes UNWRAPPED so consecutive points never jump by more than 180 degrees; the first point is exactly a, the last is b modulo 360 in longitude)
  - `interface PlanePosition { lat: number; lon: number; bearing: number; estimated: boolean }`
  - `planePosition(from: LatLon, to: LatLon, fraction: number | null, real: LatLon | null): PlanePosition | null`: `fraction === null && real === null` returns null; a real position wins (`estimated: false`, bearing from real to `to`); otherwise the interpolated point (`estimated: true`), bearing = bearing from that point toward `to`
- Produces (`progress.ts`): `planeFraction(status: FlightStatus, progress: number | null): number | null`: `cancelled` or `diverted` → null; `landed` → 1; `scheduled`/`delayed` → 0; otherwise `progress ?? 0.5`. `FlightPath` must use this function instead of its own inline logic (same behaviour: no plane for cancelled/diverted).
